# StockWise — Final Project Report

## Abstract

StockWise is an educational inventory and stock-out analysis project that demonstrates how raw product, supplier, inventory, purchase-order, and stock-movement records can be prepared and analysed through a reproducible data workflow. Python and Pandas generate and clean the data, Oracle SQL/PLSQL defines the relational reporting layer, and Streamlit, Excel, and Power BI provide reporting interfaces and design specifications.

The implementation uses a fixed-seed synthetic dataset. The cleaned snapshot contains 80 products and 12 suppliers. In that snapshot, 33 products are classified as stock-out and 14 as low stock. The calculated inventory value is 9,795,978.27 dataset currency units. Across 240 synthetic purchase-order lines, 149 deliveries are later than their expected dates. These are results from teaching data and are not claims about a real business.

## 1. Introduction and Problem Statement

Retail and distribution businesses must balance product availability against the cost of holding excess stock. Disconnected inventory and replenishment records can make it difficult to identify stock-out products, items approaching their reorder thresholds, inventory value by category, and suppliers with late deliveries.

StockWise addresses this analysis problem by building a documented pipeline from raw records to cleaned data, a relational star schema, business queries, Python visualisations, and dashboard/reporting assets.

## 2. Objectives

1. Generate or source structured inventory-related data and document data-quality issues.
2. Clean duplicate, missing, invalid, and inconsistent records using explicit rules.
3. Calculate stock-out, low-stock, inventory-value, stock-movement, and supplier lead-time measures.
4. Build a Python, Oracle SQL/PLSQL, Excel, Streamlit, and Power BI reporting workflow.
5. Validate data integrity and compare Python totals with Oracle query results when Oracle execution is available.

## 3. Dataset Description

### 3.1 Source and reproducibility

The project uses a synthetic teaching dataset generated by `src/01_generate_data.py` with NumPy random seed 42. The reference inventory snapshot date is 25 November 2026. Stock movements cover the 90-day period from 28 August to 25 November 2026.

The dataset is deliberately synthetic so that duplicate records, missing values, invalid numeric values, and inconsistent text labels can be introduced reproducibly. It must not be interpreted as real business data.

### 3.2 Dataset structure

| Dataset | Raw rows | Clean rows | Main purpose |
|---|---:|---:|---|
| Products | 81 | 80 | Product, category, cost, reorder level, primary supplier |
| Suppliers | 13 | 12 | Supplier name, region, rating |
| Inventory | 80 | 80 | One inventory snapshot per product |
| Purchase Orders | 241 | 240 | Order quantities and delivery dates |
| Stock Movements | 1,761 | 1,760 | Incoming and outgoing stock events |
| **Total** | **2,176** | **2,172** | |

### 3.3 Data cleaning

The cleaning script preserves raw files and writes separate clean CSVs. All detected changes are recorded in `reports/cleaning_log.csv` with dataset, issue, applied rule, and affected-row count.

| Dataset | Issue found | Cleaning action | Rows affected |
|---|---|---|---:|
| Products | Exact duplicate | Keep first identical row | 1 |
| Products | Missing category | Replace with Unclassified | 1 |
| Products | Negative unit cost | Replace with median valid unit cost | 1 |
| Products | Inconsistent category whitespace/case | Trim and standardise title case | 1 |
| Suppliers | Exact duplicate | Keep first identical row | 1 |
| Suppliers | Missing region | Replace with Unknown | 1 |
| Suppliers | Inconsistent region whitespace/case | Trim and standardise title case | 1 |
| Inventory | Missing reserved quantity | Fill with 0 and log the correction | 1 |
| Inventory | Implausible available quantity below -1000 | Recalculate from opening + received − issued | 1 |
| Purchase Orders | Exact duplicate | Keep first identical row | 1 |
| Purchase Orders | Missing expected delivery date | Impute order date plus median observed expected lead time (7 days) | 1 |
| Stock Movements | Exact duplicate | Keep first identical row | 1 |
| Stock Movements | Inconsistent movement label | Trim, uppercase, and map ISSUE/ISSUED to OUT | 1 |

Valid negative available quantities are retained because they represent stock-out conditions. Missing primary identifiers are not fabricated.

## 4. Business Rules and Metrics

- **Stock-out:** available quantity <= 0.
- **Low stock:** available quantity > 0 and <= reorder level.
- **Healthy stock:** available quantity > reorder level.
- **Inventory value:** available quantity × unit cost.
- **Supplier lead time:** actual delivery date − order date, in calendar days.
- **Delayed delivery:** actual delivery date is later than expected delivery date.
- **Net movement:** received units minus issued units.

The inventory-value metric follows the defined project rule and can include negative values for stock-out records. The synthetic data does not specify a real-world currency, so monetary values are labelled dataset currency units.

### 5.2 Oracle star schema

The planned Oracle model has three dimensions and three fact tables:

- Dimensions: DIM_PRODUCT, DIM_SUPPLIER, DIM_DATE.
- Facts: FACT_INVENTORY, FACT_STOCK_MOVEMENT, FACT_PURCHASE_ORDER.

Surrogate dimension keys are used with unique natural source identifiers. Fact tables reference dimensions through foreign keys. Date roles in purchase orders represent order, expected delivery, and actual delivery dates.

The schema and relationship diagram are in `sql/schema.sql`, `docs/star_schema.svg`, and `docs/Star_Schema_Notes.md`.

### 5.3 Pipeline implementation

1. `src/01_generate_data.py` creates reproducible raw CSV files.
2. `src/02_clean_data.py` produces clean CSVs and the quality log.
3. `sql/schema.sql` defines Oracle tables and constraints.
4. `src/03_load_sql.py` loads clean records into Oracle and exports seven SQL query results when connected.
5. `src/04_analysis_charts.py` creates seven PNG charts.
6. `notebooks/Analysis.ipynb` documents data loading, quality review, metrics, supplier analysis, movements, charts, and findings.
7. `app/streamlit_app.py` provides an interactive dashboard.
8. `src/05_build_excel.py` creates an Excel workbook with source sheets, summaries, charts, and a cross-check sheet.
9. Power BI model, DAX measures, and three-page report layouts are documented in `powerbi/`.

## 7. Insights and Recommendations

1. **Review stock-out products first.** 33 of 80 products are at or below zero available quantity in the snapshot. Confirm demand and physical stock before replenishment.
2. **Prioritise low-stock products.** Another 14 products are above zero but at or below reorder level. These should be reviewed before they become stock-outs.
3. **Investigate Stationery availability.** Stationery has the highest number of stock-out products in this generated dataset. Review its stock movement and reorder settings.
4. **Review supplier delivery reliability.** 149 of 240 orders are later than expected. Compare supplier-level lead times and late-order counts before changing supplier policies.
5. **Separate inventory value from service level.** Home & Kitchen has the highest recorded inventory value, while Stationery has the most stock-outs. High inventory value does not necessarily mean products are available when needed.
6. **Validate the analysis with real operational data.** The synthetic dataset is suitable for demonstrating the workflow but not for making purchasing or supplier decisions.

## 9. Limitations and Pending Work

- The data is synthetic and does not include real demand, sales, costs, or supplier contracts.
- Inventory contains one snapshot date; historical daily inventory is not directly measured.
- The estimated stock-out trend is reconstructed from opening stock and movements.
- Oracle SQL/PLSQL scripts and the loader are present, but execution awaits an Oracle instance and credentials.
- The Power BI data model, DAX, and three-page design are documented; the PBIX file still needs to be created and validated in Power BI Desktop.
- The Excel workbook generator is present and creates the workbook locally. Native PivotTables and slicers need to be added in Excel Desktop.
- No hosted demo has been deployed.

## 10. Conclusion

StockWise demonstrates an end-to-end educational workflow for inventory and stock-out analysis: reproducible data generation, traceable cleaning, relational modelling, SQL reporting design, Python analysis, visualisation, and dashboard/report preparation. The synthetic results identify substantial stock-out and low-stock counts and a high number of delayed purchase orders in the generated records.

The project is reproducible and its limitations are documented. Before operational use, the workflow must be connected to real inventory and purchase-order data, Oracle execution must be validated, and the Power BI and Excel desktop deliverables must be completed and checked.
